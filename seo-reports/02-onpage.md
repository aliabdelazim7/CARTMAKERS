# تدقيق On-page SEO وRoute Metadata — CartMakers

**تاريخ الفحص:** 8 أكتوبر 2026  
**النطاق:** العناوين والأوصاف، H1/H2، Open Graph/Twitter، alt text، المحتوى الموجود في HTML الأولي، والروابط الداخلية لكل route عام.  
**النسخة المفحوصة:** المشروع المحلي بعد `npm run build` + استجابات HTML الأولية لعناوين الـSitemap المنشورة.  
**خارج النطاق:** بحث أحجام الكلمات، ترتيب الكلمات، فهرسة Search Console، الأداء الميداني، وتحليل الباك لينكات.

## الملخص التنفيذي

**Verified:** البناء اكتمل بنجاح وأنشأ 18 صفحة prerendered؛ ملف الـSitemap يحتوي 18 عنوانًا، وجلبت العناوين الـ18 المنشورة في هذا الفحص مباشرةً وأعادت جميعها HTTP 200 مع `<title>` وdescription وcanonical ذاتي. هذه نتيجة HTTP/HTML فقط، وليست دليلًا على أن Google فهرس الصفحات أو اختار canonical نفسه.

**أهم إصلاحات On-page:**

1. **P1 — توحيد مصدر metadata والـrender:** ما يضعه `scripts/prerender.mjs` لا يطابق دائمًا ما يضعه `updateSeo()` بعد JavaScript. `/portfolio` مثال واضح: الوصف بعد JavaScript يصبح وصف الصفحة الرئيسية العام، لا وصف الأعمال. كذلك وصف الصفحة الرئيسية ووصف كل صفحة مشروع يتغيران بعد التحميل. H1 والنص الأولي لا يطابقان واجهة التطبيق في الصفحة الرئيسية وPortfolio وPolicies.
2. **P1 — توسيع المحتوى الأولي:** HTML صفحات المشروع لا يتجاوز اسم المشروع وملخصًا وروابط عامة؛ لا يحتوي brief أو insight أو features أو صورة المشروع. HTML الـPortfolio يحتوي قائمة روابط وملخصات لكنه لا يحتوي صور الأعمال أو H2. HTML السياسات يعرض مقدمة ونموذجًا واحدًا فقط من محتوى الصفحة ذات الأقسام الـ11.
3. **P2 — تمييز البحث والخدمة في الصفحات الأساسية:** عنوان الصفحة الرئيسية الحالي لا يقول مباشرةً إن CartMakers تبني مواقع ومتاجر إلكترونية. 11 عنوانًا من 18 أقصر من 30 حرفًا وفق عدّ النص في ملفات البناء؛ الأوصاف الحالية كلها بين 50 و160 حرفًا. العنوان القصير ليس وحده دليل مشكلة ترتيب، لكنه فرصة محددة لتحسين وصف الصفحة في نتائج البحث وفق معيار لوحة المشروع.
4. **P2 — تحسين مشاركة الصور:** جميع الصفحات تستخدم شعار CartMakers نفسه كـ`og:image` و`twitter:image`، مع alt موحّد لا يصف صورة مشروع بعينه. صفحات المشاريع والـPortfolio لديها أصلًا صور WebP محلية لا تظهر في HTML الأولي.
5. **الروابط الداخلية الأساسية موجودة:** الـPortfolio يربط إلى جميع صفحات المشاريع الـ15، وصفحة المشروع تعود إلى Portfolio وإلى نموذج التواصل. الفرصة هي إضافة روابط سياقية إلى أقسام الخدمات والباقات من صفحات المشاريع، وإظهار هذه الروابط في HTML الأولي لا بعد React فقط.

لا يتضمن هذا التقرير توقعات رقمية للترتيب أو الزيارات، ولا نتائج بحث للكلمات؛ لا توجد بيانات كافية لإثباتها.

## النطاق وطريقة التحقق

- قرأت `HANDOFF.md` و`plan.md` وملف الاستراتيجية `pasted_content.txt` قبل التحليل. موجز الاستراتيجية يطلب عنوانًا ووصفًا وH1/H2 وروابط وصورًا لكل صفحة، ويمنع اختلاق بيانات أو حشو كلمات.
- راجعت `index.html`، `src/main.jsx`، `scripts/prerender.mjs`، `public/manus-routes.json` و`public/sitemap.xml`.
- شغّلت `npm run build`؛ اكتمل وصرّح `Prerendered 18 public routes.` ثم استخرجت metadata/headings/links/images من ناتج HTML دون تشغيل JavaScript.
- جلبت عناوين Sitemap الـ18 من `https://www.cart-makers.com/sitemap.xml` دون تشغيل JavaScript؛ أعادت جميعها `200`. قيم الجدول التالي تمثل HTML الأولي المعلن في الاستجابة؛ سجلات المحتوى مصدرها النسخة المنشورة/البناء الجاري.
- راجعت من الشيفرة ما يحاول التطبيق تغييره في `useEffect` بعد التحميل. **لم أجرِ فحص Chromium للـDOM بعد hydration ضمن هذا التقرير**؛ لذلك أصف التغييرات بعد JS بأنها سلوك محدد في الكود، لا نتيجة اختبار متصفح مستقل.
- لم تُستخدم مصادر خارجية في هذا التقرير؛ كل الاستنتاجات أدناه مرتبطة بملفات الموقع واستجاباته.

> قاعدة القياس الخاصة بلوحة المشروع، كما وردت في إرشادات SEO المتاحة للمشروع: عنوان 30–60 حرفًا ووصف 50–160 حرفًا. الأطوال المذكورة أدناه عدّ محارف النص في HTML، ولا تعني ضمان عرض العنوان كاملًا في نتائج البحث.

### المحتوى الظاهر قبل JavaScript

- `/`: HTML الأولي في `scripts/prerender.mjs` يتضمن H1 وفقرة مختصرة وH2 وفقرة/روابط. لا يتضمن متن أقسام الصفحة الرئيسية كما هي في React؛ الروابط الأولية هي Portfolio ونموذج التواصل فقط.
- `/portfolio`: HTML الأولي يتضمن مقدمة وقائمة روابط الـ15 مشروعًا وملخصًا لكل رابط، وهو مفيد لاكتشاف الروابط، لكنه يفتقد صور المشروع وH2 والفلاتر وباقي بنية الصفحة المرئية.
- `/policies`: HTML الأولي يحتوي مقدمة، بندًا واحدًا عن 50% مقدمًا، وروابط؛ بينما واجهة التطبيق تحوي 11 بندًا وملخصًا. هذا اختلاف جوهري في كمية المعلومات التي تصل قبل React.
- `/projects/{slug}`: HTML الأولي لكل صفحة يحوي عنوان المشروع وملخصًا عامًا ورابط العودة للـPortfolio ورابط التواصل فقط. لا يظهر الـtag أو brief أو insight أو features أو التنبيه الذي يوضح أن الصفحة مرجع بصري ولا تنسب نتائج أو تنفيذًا غير موثق.
- ملف `index.html` المصدر نفسه يبدأ بـ`<div id="root"></div>`، لكن هذا **ليس** وحده وصفًا للاستجابة المنشورة؛ سكربت البناء يملأ HTML الداخلي. الحكم أعلاه مبني على ملفات `dist` المولدة، لا على قراءة shell المصدر فقط.

**إجراء P1 دقيق:** اجعل بيانات route واحدة مصدرًا لكل من prerender وReact، أو ولّد HTML من القوالب/مكوّنات مشتركة. يجب أن يتضمن HTML الأولي النص نفسه الذي يراه المستخدم: الصفحة الأساسية، الفقرات، العناوين، الصور، وروابط `<a href>` الفعلية. أضف اختبار build يقارن لكل route على الأقل title/description/H1 ووجود المحتوى والصورة، ويكشف اختلاف النص بعد التغييرات؛ لا تنشئ وصفًا أو نتائج مشاريع غير موجودة في البيانات.

## Metadata وOpen Graph/Twitter

### ما تم التحقق منه

- كل عنوان من الـ18 لديه `<title>` و`meta description` وcanonical ذاتي؛ عناوين OG `og:url` في HTML الأولي تطابق المسار القياسي.
- على مستوى HTML الأولي، الصفحات الـ18 تستخدم `og:site_name=CartMakers` و`og:locale=ar_EG` و`twitter:card=summary_large_image`. `og:type=website` للرئيسية وPortfolio وPolicies؛ و`article` لصفحات المشاريع.
- `og:title` و`twitter:title` route-specific. أوصاف OG/Twitter route-specific للصفحات الداخلية. **الصفحة الرئيسية استثناء:** وصف OG/Twitter هو `CartMakers بتبني وتصلّح وتكبّر أنظمة التجارة.`، بينما meta description أطول ويذكر المتجر والـCheckout والدفع والتوصيل والتتبع.
- كل route يستخدم الصورة نفسها: `https://www.cart-makers.com/assets/cartmakers-primary-light.svg`. `og:image:alt` و`twitter:image:alt` موحدان: `CartMakers — أنظمة تجارة تشتغل وتكبر`.
- بعد React، `updateSeo()` يغيّر القيم: وصف الرئيسية يصبح `CartMakers بتبني وتصلّح وتكبّر أنظمة التجارة للبراندات اللي عندها طلب.`؛ وصف Portfolio يأخذ الوصف العام نفسه بدل وصف الأعمال؛ وصف كل مشروع يلحق به `مرجع بصري ومعلوماتي من CartMakers.`. نتيجة ذلك أن title/description/social metadata بين HTML الأولي وDOM قد تختلف.
- `updateSeo()` لا يغيّر مسار OG-image؛ لذلك يظل شعار الشركة صورة المشاركة، حتى لصفحات المشاريع. ملفات صور المشاريع المحلية موجودة في `/portfolio/{slug}.webp` ومستخدمة في React بعد التحميل، لكنها لا تدخل صورة metadata ولا HTML الأولي.

### التعديلات الدقيقة

1. انقل لكل route كائنًا موحدًا به `title`, `description`, `h1`, `ogImage`, و`imageAlt`; استخدمه في `scripts/prerender.mjs` و`updateSeo()`. أصلح branch الخاص بـPortfolio صراحة، ولا تسمح له بالرجوع لوصف الصفحة الرئيسية.
2. وحّد وصف كل route في `<meta name="description">`, `og:description`, و`twitter:description` في الاستجابة الأولى وبعد JS. التوصيات الدقيقة للرئيسية وPortfolio وPolicies مذكورة في الجدول أدناه.
3. لكل صفحة مشروع، استخدم الوصف الحالي الخاص بها ثم لاحقة واحدة صادقة: **` — مرجع بصري ومعلوماتي من CartMakers.`**، واجعل القيمة نفسها في HTML الأولي وReact وOG وTwitter. حافظ على تنبيه الصفحة بأن النتائج/التقنيات/التنفيذ لا تُنسب ما لم توثق؛ لا تضف أرقام أداء أو claims.
4. استبدل صورة الشعار في metadata بصورة مشاركة مناسبة وموجودة فعلًا لكل صفحة: للصفحة الرئيسية/Portfolio صورة علامة أو تصميم اجتماعي ملائم، ولصفحات المشاريع استخدم صورة الصفحة المقابلة من `/portfolio/{slug}.webp` إذا كانت مناسبة للمشاركة، أو أنشئ نسخة مشاركة مشتقة منها. حدّث `og:image:alt` و`twitter:image:alt` إلى وصف صادق للصورة المعينة، مثل `لقطة من واجهة {project.title} — {project.tag}` بعد مطابقة alt للصورة بصريًا. لا تضع النص التسويقي العام كـalt لصورة مشروع.
5. `og:locale:alternate` المذكور في HANDOFF غير ظاهر في `index.html` أو كود prerender الحالي. لا تضف لغة بديلة لمجرد وجود وسم؛ احسم أولًا هل `/en` صفحة ستنشر فعلًا، ثم أضف بيانات اللغة المقابلة فقط عند وجود نسخة بديلة حقيقية ومربوطة.

## Alt text وصور المحتوى

**Verified من الملفات:** React يعطي صورة الشعار alt النص `CartMakers — Ecommerce Systems & Growth`. صور بطاقات الـPortfolio والسلايدر وصورة صفحة المشروع تستخدم `alt={project.title}` (أي اسم المشروع فقط). أما HTML الأولي الناتج فليس به أي `<img>` في أي من الـ18 route، وبالتالي لا توجد alt text في النسخة الأولية، حتى في Portfolio وصفحات المشروع التي تعرض صورة بعد JavaScript.

**Actions:**

- أدرج صورة صفحة المشروع في HTML الأولي بعنوان ملف محلي، أبعاد ثابتة، وalt نصي. استخدم نمطًا مثل **`لقطة شاشة لواجهة {project.tag} — {project.title}`** بعد التحقق من أن الملف فعلًا لقطة لذلك الموقع؛ alt ليس مكانًا لتكرار كلمات بحث غير ظاهرة بالصورة.
- بطاقات Portfolio: اجعل alt يصف محتوى الصورة أو الواجهة الظاهرة، لا اسم البراند وحده. إن كانت الصورة تكرارًا زخرفيًا بجانب رابط يحمل الاسم نفسه، استخدم alt فارغًا للصورة الزخرفية بدل تكرار النص، مع بقاء الرابط له اسم قابل للفهم.
- الشعار: استخدم alt موجزًا مثل `CartMakers`، أو alt فارغًا إذا كان نص الرابط المجاور يعرّف العلامة بالكامل ولا تضيف الصورة معلومة أخرى.
- أضف alt خاصًا لكل صورة تستخدم في social metadata كما سبق؛ alt الخاص بـ`<img>` لا يحل محل `og:image:alt`/`twitter:image:alt`.
- لم أصف محتوى الصور من الرؤية؛ الاقتراحات الوصفية أعلاه مبنية على أسماء ووسوم البيانات في الكود وتحتاج مطابقة بصرية قبل النشر.
